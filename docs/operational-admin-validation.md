### Environment-specific component registration

The first live release gate exposed a production-only Blob client provider missing from the generated component map. API authentication succeeded, but the admin shell was blank. The prior stable deployment was promoted while fixing the build. The import-map configuration now always registers the installed Blob provider, even when local Blob credentials are absent; the build command regenerates the map before Next compilation. tests/admin-import-map.cjs reproduces credential-free regeneration and asserts the provider and custom fields remain registered. This prevents the local/production configuration mismatch rather than patching only one generated file.

The import-map generator is deliberately CLI-only: installed Payload3.94 forwards import-map settings into the client config, so a runtime generator function would break RSC serialization. tests/import-map-runtime.mjs asserts the browser-bound settings contain no function. The restored map/build passed fresh local login/dashboard/navigation, actual request storage and CSV download tests before redeployment.
